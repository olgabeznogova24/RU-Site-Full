# CeramicaDecor — рабочие правила проекта

## Что это за проект

Это **статическая вёрстка (дизайн-пакет) для передачи программисту**, а не рабочий сайт и не Laravel-интеграция. Программист потом подтянет товары, цены, фото, SEO и формы из внутренней системы.

Главное следствие: **не вшивать данные в HTML**. В вёрстке должны быть только шаблоны и демонстрационные примеры. Не создавать отдельный HTML-файл под каждый товар.

Полное ТЗ — `readme.md`. При расхождении между этим файлом и `readme.md` источником правды считается `readme.md`.

Файл `ТЗ_CeramicaDecor_новый_дизайн_Laravel.md` устарел, описывает отменённый формат работы. Не использовать.

## Что не относится к сайту

- `Booklet OV 2026/` — печатный буклет;
- `Brandbook/` — брендбук;
- `outputs/` — рабочая папка для отладочных скриншотов, исключена из git;
- `D:\Ceramica Decor\_архив_outputs` — архив старых деплоев вне проекта.

## Правила, которые легко нарушить

- **Округление цен до 1000 ₽ — только на главной.** `767 994 ₽` выводится как `768 000 ₽`. На каталожных и других страницах цены не округлять.
- **Никаких публичных ссылок на `login.html` и `password-recovery.html`.** Это внутренние страницы сотрудников. Их нельзя добавлять в шапку, футер, модалку поиска, публичные CTA и `sitemap.xml`. У обеих `robots: noindex, nofollow`.
- **Карточка товара открывается отдельной страницей, а не модальным окном.** Ссылка — обычный `<a href="...">`, чтобы её видели пользователи и поисковики. Модалки допустимы для форм заявки, видео и поиска.
- **Задержка мегаменю 300 мс** — `hoverSwitchDelay` в `script.js:347`. Нужна, чтобы вести мышку по диагонали к карточкам справа, не задевая соседние разделы. Не убирать.
- **`Реставрация` не отдельный пункт верхней навигации** — ссылка живёт внутри меню каталога.

## Ссылки на товары: правило `?product=`

Отдельных файлов под каждый товар нет и делать их не нужно. Карточка ведёт на подходящий шаблон с демонстрационным параметром, который программист заменит на реальный URL:

```
product-drovyanoi-kamin-template.html?product=kamin-versal
```

Это правило действует одинаково для каталога, результатов поиска и карточек реализованных проектов на главной.

Шаблоны товаров:

| Шаблон | Для каких разделов |
|---|---|
| `product-izrazec-template.html` | все изразцы |
| `product-drovyanoi-kamin-template.html` | камины, печи, печи-камины из наличия, мраморные камины и порталы, плитка ручной работы, фасадная керамика, метлахская плитка, сувенирная продукция |
| `product-barbekyu-kompleks-albion-template.html` | барбекю комплексы |
| `product-restavraciya-izrazcovye-pechi-template.html` | реставрация |
| `product-components-astov-ps-7363-template.html` | всё для монтажа (топки, электроочаги) |

## Как править файлы

**Шапка и футер продублированы в 39 HTML-файлах.** Любую правку навигации делать скриптом по всем файлам сразу, иначе страницы разъедутся. Править вручную в одном файле — почти всегда ошибка.

**Кодировка.** Файлы в UTF-8, в git хранятся с LF (см. `.gitattributes`). Имена части файлов содержат кириллицу и пробелы. При массовых заменах через PowerShell читать и писать через `[System.Text.Encoding]::GetEncoding(28591)` (latin1, 1 байт = 1 символ) — тогда кириллица и BOM не искажаются. Обычный `Get-Content`/`Set-Content` в PowerShell 5.1 портит UTF-8.

**Инлайновый CSS.** В 39 страницах есть блоки `<style>` (в `catalog.html` и `restoration.html` — по 30 КБ). Общие стили живут в `style.css`.

**Осторожно с CSS, привязанным к именам файлов.** Встречаются селекторы вида `img[src$="имя.jpg"]`. При замене картинки такие правила надо искать и обновлять, иначе они молча ломают кадрирование.

## Изображения

Различать дизайн-ассеты (логотип, иконки, шрифты, hero-фоны, декоративные изображения) и контент (фото товаров, изразцы, 360-фото).

Рабочие версии картинок названы по схеме `banner-<раздел>_desktop.webp` / `_mobile.webp` (130–420 КБ) и `contacts_showroom_NN_sm.jpg`. Рядом лежат исходники по 20–47 МБ с именами вида `banner_kaminy.jpg`, `contacts_9.jpg` — **их нельзя подключать в вёрстку**.

Перед подстановкой картинки в карточку проверять пропорцию: карточки мегаменю ждут ~1.50 (например 1600×1067), широкие `_desktop`-баннеры 1920×620 для карточек не подходят.

Список неиспользуемых файлов — `images-unused-review.md` (рабочий документ, можно удалить).

## Проверка перед передачей

- нет ссылок на несуществующие локальные `.html`;
- все картинки из `src`/`srcset` существуют на диске;
- открываются главная, каталог, все 15 разделов, `catalog-izrazcy.html` с первой страницей карточек, `404.html`, `login.html`, `password-recovery.html`;
- работают фильтры, пагинация, модалки, поиск, мобильное меню;
- формы показывают состояние успешной отправки;
- ширины 1440, 1280, 768, 390, 360 px.

Endpoint форм `https://ceramicadecor.ru/feedback/ceramicadecor_pro` (38 мест) — временный, программист заменит.

## Git

- Один коммит = одно законченное осмысленное изменение. Описание по сути, не датой.
- **Не пушить на GitHub без явной просьбы.** Коммитить можно.
- Репозиторий тяжёлый (`.git` ~1,4 ГБ): в истории лежат исходники JPG по 30–47 МБ. Удаление файлов размер истории не уменьшает.
